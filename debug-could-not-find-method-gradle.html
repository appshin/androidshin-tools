"Could not find method implementation() for arguments"

I pasted a dependency line from a README, synced, and Gradle rejected it — not with "unknown library" but with something stranger: it couldn't find the method implementation(). A method I use in every project. The build file wasn't broken so much as I'd written the right idea in the wrong dialect, or in the wrong place.

The short version: this means Gradle doesn't recognize the function you called in that spot. Three usual reasons: you mixed Groovy and Kotlin DSL syntax, you put the call in the wrong block, or the plugin that defines the method hasn't been applied yet. The fix is matching syntax and placement to your build file.

The error

Could not find method implementation() for arguments
[androidx.core:core-ktx:1.x.x] on object of type
org.gradle.api.internal.artifacts.dsl.dependencies...

The wording is generic and applies to many methods — implementation, android, kotlinOptions, and others. Whatever method it names, the diagnosis is the same: it's not available where you called it.

Cause 1 — Groovy vs Kotlin DSL syntax

Gradle build files come in two flavors, and they don't share punctuation. Groovy (build.gradle) and Kotlin (build.gradle.kts) write the same dependency differently:

// Groovy — build.gradle
implementation 'androidx.core:core-ktx:1.12.0'

// Kotlin — build.gradle.kts
implementation("androidx.core:core-ktx:1.12.0")

Paste a Groovy line (no parentheses, single quotes) into a .kts file and Kotlin can't parse the call — hence "could not find method". Check your file's extension first and match the snippet to it. This is the single most common cause, because snippets online come in both styles and rarely say which.

Cause 2 — the call is in the wrong block

implementation() only exists inside a dependencies { } block. Drop it at the top level of the file, or inside android { }, and the method genuinely isn't defined there. The same is true for other methods: kotlinOptions belongs inside android { }, repositories inside repositories { }. If the error names a method you know exists, check that it's nested in the block that provides it.

Cause 3 — the plugin isn't applied

Many methods are contributed by plugins. The whole android { } block, for instance, only exists once the Android Gradle Plugin is applied. If you call something before (or without) applying the plugin that defines it, Gradle can't find the method. Make sure the plugins { } block at the top applies what you need:

plugins {
    id("com.android.application")
    id("org.jetbrains.kotlin.android")
}

Order matters here too — the plugin has to be applied before the block or method it provides is used.

Before rewriting anything, glance at the file name in the tab. Half of these errors are solved the instant you notice you're editing a .kts file with Groovy syntax, or vice versa. The extension tells you which punctuation the whole file expects.

A quick way to place the blame

  • Is the file .gradle or .gradle.kts? Match quotes and parentheses to it.
  • Is the call inside the right block? implementation → dependencies; kotlinOptions → android.
  • Is the plugin that defines it applied, and applied before the call?
  • Did you copy from a different Gradle era? Very old snippets use compile instead of implementation — a related "method not found" once compile was removed.

Library names and versions above are examples — use your own.
